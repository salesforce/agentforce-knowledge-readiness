# Agentforce Knowledge Readiness

> **⚠️ This is an accelerator, provided as is and not an official Salesforce product.** Test it in a sandbox or scratch org before any production use, and review Einstein/Data Cloud credit consumption for your Knowledge Base size first.

> Built by Salesforce forward deployed engineers with AI assistance — code generated by Claude (Anthropic) under human direction, design, and review.

![Source API](https://img.shields.io/badge/Source_API-66.0-blue)
[![Accessibility](https://img.shields.io/badge/Accessibility-WCAG_2.2_AA_(targeting)-yellow)](accessibility/wcag-2.2-aa-acr-knowledge-readiness.md)

An AI agent is only as smart as the documentation feeding it. This tool helps you catch duplicates, outdated information, and confusing phrasing before your customers do.

Agentforce Knowledge Readiness is a native Salesforce Lightning App that gives admins a one-click Knowledge Base health scan before Agentforce go-live. It scores every article on a **Knowledge Readiness Score (0–100)** across six dimensions — Completeness, Structure, Clarity, Freshness, Duplication, and Conflict — and produces impact-rated, actionable recommendations for each article.

Scoring itself never modifies your articles. When an admin chooses to act on a recommendation, the **AI Fix** flow (available in the **Actions** tab) generates a rewritten Draft on demand. Drafts always require human review before publishing, so the original article stays live and unchanged until an editor approves the update.

## Quick start

If your org already meets the [Prerequisites](#prerequisites) (Einstein Generative AI, Data 360, and Lightning Knowledge all enabled), the full install is about **5 minutes**. Run each command below, one at a time, replacing `<target-org>` with an alias of your choice (e.g. `dev`, `my-org`).

**1. Clone the repo**

```bash
git clone <repository-url>
```

**2. Move into the folder that was just created**

```bash
cd <cloned-directory>
```

**3. Log in to your sandbox (opens a browser)**

```bash
sf org login web --alias <target-org> --instance-url https://test.salesforce.com
```

Deploying to a production or Developer org instead? Drop the `--instance-url` flag.

**4. Deploy the code to your org**

```bash
sf project deploy start --source-dir force-app --target-org <target-org>
```

**5. Give yourself permission to use the tool**

```bash
sf org assign permset --name KB_Assessment_Admin --target-org <target-org>
```

**6. Open the app in your browser**

```bash
sf org open --target-org <target-org> --path "/lightning/app/KB_Readiness_Assessment"
```

Then finish two setup steps inside Salesforce:

- **Activate the Knowledge article record page** (Setup → Lightning App Builder — see [Installation Step 5](#activate-record-page)). Without this, per-article results won't show up on the Knowledge article page.
- **Run the in-app Setup Wizard** from the **Setup** tab to configure content fields and your search index.

> **First time deploying?** Read the full [Prerequisites](#prerequisites) and [Installation](#installation) sections below — they cover the org features that must be enabled first, extra permission sets for other user personas, and how to fix common deploy errors.

## The Problem

Poor or fragmented Knowledge Bases cause Agentforce hallucinations, lower deflection rates, and stalled rollouts. There is no native tool to evaluate whether a KB is ready for agent consumption before go-live.

This tool fills that gap: scan, score, recommend — and, on demand, draft AI fixes for review.

## Prerequisites

This solution is fully native to Salesforce — no external APIs, no managed package dependencies. It does, however, depend on several platform features that must be enabled in the target org **before** deployment.

### Tooling on your machine
- **Git** — to clone the repository
- **Salesforce CLI** (`sf`) — install from [the Salesforce CLI page](https://developer.salesforce.com/tools/salesforce-cli)
- **API version 66.0** or later (the project's `sourceApiVersion`)

### Required Salesforce features
All three must be enabled before the deploy succeeds or the tool runs correctly:

| Feature | Why it's needed | Where to enable |
|---------|-----------------|-----------------|
| **Lightning Knowledge** | The `Knowledge__kav` object is the core data source. The deploy and runtime both fail without it. | Setup → Knowledge Settings → Enable Lightning Knowledge |
| **Einstein Generative AI** | Unlocks `ConnectApi.EinsteinLLM` (the runtime entry point for all LLM scoring) **and** the ability to deploy the 12 `GenAiPromptTemplate` metadata files. Missing this causes ~40 cascading deploy errors. | Setup → Einstein Setup → Einstein Generative AI |
| **Data 360** | Tier 2 semantic vector search for the dedup pipeline, via `ConnectApi.CdpQuery`. **Requires a search index over Knowledge Article Version (`Knowledge__kav`)** — either an Agentforce Data Library or a custom Data 360 search index — so the Duplication and Conflict scoring dimensions can retrieve semantically similar articles. The index name is configured on the Setup Wizard's Essentials screen. See [Search index: ADL vs custom](#search-index-adl-vs-custom) below for the publish-status implications. | Setup → Data Cloud / Agentforce Data Library |

> Lightning Knowledge is generally **not reversible** once enabled — confirm before turning it on in production.

### User-level requirements (post-deploy)

Four distinct things must be set on the User record of anyone who runs the tool (or whose context the Data 360 connector authorizes against). They are **separate** from the org features above, and the second, third, and fourth are **not part of this package** — you assign them yourself:

1. **Knowledge User feature license** (User record checkbox, Setup → Users → *user* → **Knowledge User**) — gates two different things, and read access alone does not cover authoring:
   - Without it, the platform will not expose `Knowledge__kav` to that user at all — even a sysadmin gets `sObject type 'Knowledge__kav' is not supported`.
   - It is **also required to author articles.** A user can hold object read + all the permission-set grants below and still **read/score** articles fine, yet the **write** actions (Fix with AI, merge) fail with a bare `Insufficient Privileges` from `KbManagement.PublishingService.editOnlineArticle` until this license is checked. It is a **feature license**, not a permission-set grant — assign it on the User record (or via a permission-set-license assignment), not through the KB permission sets. Enable it on every user who will run **Fix with AI** or **merge**, not just read-only assessors.
2. **The shipped permission sets for the persona** (see [Permission model](REFERENCE.md#permission-model)) — `KB_Assessment_Setup_Admin` (config), `KB_Assessment_Admin` (run/analyse), `KB_Assessment_Viewer` (read-only), and the **additive** `KB_Knowledge_Author` (Knowledge write access for Fix with AI / merge, layered on top of the Manager set). These are deployed by this package and grant app/tab/object access. A user who runs assessments **and** fixes/merges articles needs **both** `KB_Assessment_Admin` and `KB_Knowledge_Author`.
3. **Platform user permissions NOT shipped with this package — assign these to the running user.** The package's permission sets deliberately do **not** grant the platform-wide Einstein/Data 360 entitlements; those are org-level licenses you control. A running user needs, at minimum:
   - **Data Cloud user** — required for the Tier 2 vector-search calls (`ConnectApi.CdpQuery`) to authorize. Without it the dedup pipeline silently falls back to SOQL keyword matching.
   - **Prompt Template user** (sometimes surfaced as "Prompt (Template) user") — required for `ConnectApi.EinsteinLlm.generateMessagesForPromptTemplate()` to authorize. Without it every LLM scoring call fails and Completeness/Structure/Clarity fall back to the baseline (60) score.

   > These two permissions **blocked an internal build** when missing — the app deployed cleanly but produced only fallback scores at runtime. Assign them (via a standard permission set such as the platform's **Data Cloud** and **Prompt Template User** permission sets, or your own permset that includes the equivalent system permissions) to every user who will run an assessment, alongside the shipped KB permission set.

4. **Knowledge data-plane access — assign yourself** (not shipped with the package). The KB permission sets grant app/object access to `Knowledge__kav`; they deliberately do **not** grant field-level security or the article-management action permissions, because how you manage your Knowledge base (field names, who may version and publish articles) is org-specific. Assign these to any user who performs **Fix with AI** or **Merge** — the write actions that create a Draft via `KbManagement.PublishingService.editOnlineArticle`.

   | Permission | Where to assign | Needed for |
   |---|---|---|
   | FLS **Read** on `Title` + Content Field Mapping fields (e.g. `Summary`, `FAQ_Answer__c`, `Chat_Answer__c`, `KCSArticle_Resolution__c`) | Object Manager → Knowledge → Fields → Field-Level Security | Read-only scoring (batch assessments, Preview results) |
   | FLS **Read + Edit** on the same fields | Same as above | Fix with AI, Merge |
   | **Manage Articles** (`ManageKnowledge`) | User permission (permission set or profile) | Fix with AI, Merge |
   | **Publish Articles** (`PublishArticles`) | User permission (permission set or profile) | Publish Golden Record |

   Together with `KB_Knowledge_Author` and the **Knowledge User feature license** (item 1), these are the complete set needed to author drafts.

   > ⚠️ **Delete permission on `Knowledge__kav` is required to publish.** `KB_Knowledge_Author` grants **Delete** on purpose — don't strip it. Publishing a draft supersedes the prior article version, and the platform requires object **Delete** to complete that step. Without it, publish/Approve fails with the platform's ambiguous *"You can't perform this action. Be sure the action is valid for the current state of the article, and that you have permission to perform it."* — which reads like a state problem but is really the missing Delete permission.

   If any of these are missing, the write actions fail with an actionable on-screen error — either "Field-level security … is missing. Grant … Content Scope fields" (missing FLS) or "Insufficient Privileges" (missing `KB_Knowledge_Author`, an article-management permission, or the Knowledge User license) — rather than a silent no-op. Read-only scoring is unaffected and needs none of these write permissions.

### Search index: ADL vs custom

The Duplication and Conflict dimensions, and the whole dedup pipeline, query a Data 360 search index over `Knowledge__kav`. You can back that index two ways, and **the publish-status behavior differs** — pick the one that matches how you want to manage it.

> **Do not rely on "make your ADL published-only."** Earlier guidance told customers to restrict their search index to published articles. That is **not achievable on an Agentforce Data Library** — an ADL ingests **all versions** of an article (Draft, Online, Archived) and cannot be filtered to published-only by the customer, despite UI that may imply otherwise. Old/archived/draft versions of an article will otherwise surface as duplicate candidates. The app now handles this itself for the ADL path (see below); custom-index users handle it at index-build time.

| Path | How publish-status filtering happens | What you must do |
|------|--------------------------------------|------------------|
| **Agentforce Data Library (ADL)** | **The app filters by publish status itself.** Because an ADL ingests all versions, the app applies a publish-status prefilter on the vector query so only currently-published content is returned. This is driven by a setup checkbox — **"Is this search index an Agentforce Data Library (ADL)?"** — on the Setup Wizard's Essentials screen. | Tick the ADL checkbox on Essentials. No index-side filtering is needed (and none is possible). |
| **Custom Data 360 search index** | **You filter it yourself.** The app cannot guarantee filtering on an arbitrary custom index and cannot auto-detect whether an index is an ADL, so this path relies on the index being built to contain **only published articles**. | Configure your custom index/data stream to include **only Online (published)** articles — see [Configuring a custom search index for published-only articles](#configuring-a-custom-search-index-for-published-only-articles). In setup you acknowledge you've done this; if you skip it, expect false-positive duplicate candidates from draft/archived versions. |

#### Configuring a custom search index for published-only articles

If you use a custom Data 360 search index (rather than an ADL), build it so that only currently-published Knowledge versions are indexed. At a high level:

1. In Data 360, define (or edit) the data stream that ingests `Knowledge__kav` into the index.
2. **Filter the stream/index to published versions only** — restrict to records whose publish status is Online (i.e. exclude Draft and Archived versions). Use the publish-status field exposed by your Knowledge data model object (e.g. the SSOT publication-status field) as the filter.
3. Rebuild / refresh the index after changing the filter so the change takes effect. (Index/stream refresh is not instant — archived or unpublished versions can linger as candidates until the next refresh completes.)
4. Keep the index's indexed fields aligned with the **Content Field Mapping** you select on the Setup Wizard's Essentials screen — see [Keep your index fields and content scope aligned](#keep-your-index-fields-and-content-scope-aligned).

> Prefer not to maintain this yourself? **Create an Agentforce Data Library instead** and tick the ADL checkbox on the Essentials screen — the app then applies the publish-status filter for you.

```bash
git clone <repository-url>

```

```bash
sf org login web --alias <target-org>
```

### 3. Deploy the metadata

```bash
sf project deploy start --source-dir force-app --target-org <target-org>
```

The deploy includes Apex classes, LWC bundles, custom objects/fields, permission sets, GenAI prompt templates, and custom metadata. No profiles are shipped — access is granted exclusively through the KB permission sets. Expect 1–2 minutes.

- `Type is not visible: ConnectApi.EinsteinLLM` cascading across classes → org is missing Einstein Generative AI. Enable it and retry.
- `GenAiPromptTemplate ... Not available for deploy for this organization` → Einstein Generative AI isn't enabled. Enable it and retry.

**Post-deploy:** if LWC pages report `No apex action available for X.methodName`, some Apex classes deployed in an `IsValid: false` state. Trigger a full recompile from **Setup → Apex Classes → "Compile all classes"**.

**Read-only stakeholder access**:


## Post-Install Setup Walkthrough

After deploying, open the **Knowledge Readiness** app from the App Launcher. Other tabs show a "Setup required" guard until the wizard is completed. Navigate to the **Setup** tab.

The wizard has three steps — **Welcome → Essentials → Validate & Save** — and puts everything optional behind an **Advanced (optional)** accordion on the Essentials screen. Sensible defaults are pre-configured; the only things a first-run admin *must* set are the content fields and the search index (data categories is also on the mandatory Essentials screen). Save & finish is reachable without ever opening Advanced.

### Step 1 — Welcome

An orientation card. It explains what setup configures and reassures you that sensible defaults cover everything except your **content fields** and your **search index** — the two mandatory choices. It also lists the shipped permission sets and the platform prerequisites (Data Cloud / Prompt Template user), informational only; actual assignment happens in Setup → Permission Sets → Manage Assignments. Click **Next** to begin.

### Step 2 — Essentials

The single mandatory configuration screen. Three things live here, always visible:

- **Content Field Mapping** — select which `Knowledge__kav` fields contain the article body text that scorers read. The assessment engine concatenates these fields as the "content" for each article. **This is an explicit selection, not intelligent auto-discovery: if you leave it empty the runtime falls back to `Summary` only** — which is usually too short for meaningful scoring and produces misleadingly low scores with no warning. Always select your org's primary body fields (e.g. `Solution__c`, `FAQ_Answer__c`, `Content__c`).
- **Data Categories** — "My articles use data categories": when on, an article with no data category loses Completeness points; when off, a missing data category is informational only and does not affect the score.
- **Search index** — select the Data 360 semantic search index Tier 2 deduplication uses, and tell us whether it is an Agentforce Data Library:
  - Enable/disable toggle — when disabled, Tier 2 uses SOQL keyword matching instead.
  - **Search Index** — select from available Data 360 semantic search indexes (dropdown auto-discovers indexes in the org). If none exist, create one in Data 360 or Agentforce Data Library first.
  - **Is this search index an Agentforce Data Library (ADL)?** — tells the app how to handle publish status. **Yes (ADL):** the app applies a publish-status prefilter on the vector query so only currently-published content is returned (an ADL ingests all versions, so this filtering must happen at query time). **No (custom index):** the app cannot guarantee filtering, so you must have built the index to contain only published articles yourself, and you acknowledge that here. See [Search index: ADL vs custom](#search-index-adl-vs-custom).
  - **Max Results** — caps how many similar-article candidates the vector search returns **per article** (default: 20). Lower = fewer, higher-confidence candidates and less downstream LLM triage cost; higher = broader recall.
  - **Data Space Name** — Data 360 data space (default: "default").

> **Keep your index fields and content scope aligned.** <a id="keep-your-index-fields-and-content-scope-aligned"></a>The fields you pick in Content Field Mapping also build the text the dedup pipeline **sends to** Data 360 vector search. But what Data 360 actually **embedded** was fixed when the search index was created, and the tool can't read that back. If the index's indexed fields and your Content Field Mapping diverge, dedup quality quietly degrades. When you change one, revisit the other.

#### Advanced (optional)

All defaults work — open this accordion only to fine-tune. It groups what were previously the separate Assessment Rules and Runtime & Retrieval steps into a single settings table.

| Setting | Default | When to change it |
|---|---|---|
| **Freshness — warning threshold** (months) | 12 | Your KB churns faster or slower than "yearly staleness" |
| **Freshness — critical threshold** (months) | 24 | Same rationale as above |
| **Data Categories** (also on Essentials — same setting) | On | Turn off if your org doesn't use data categories; missing categories then don't cost Completeness points |
| **Score Weights** — Completeness / Structure / Duplication / Conflict / Clarity / Freshness (must sum to 100%) | 30 / 20 / 15 / 15 / 10 / 10 | Prioritize a specific dimension for your rollout (e.g. weight Duplication higher during a KB cleanup phase) |
| **Similar articles to scan per article** (Tier 2 Top K) | 20 | Lower for fewer, higher-confidence candidates and less LLM cost; higher for broader recall |
| **Minimum similarity to flag a match** (0–1, cosine-similarity floor) | 0.75 | Raise for fewer, higher-similarity duplicate candidates. Distinct from the article-level **Confidence Score** shown in the **Actions** tab — that's an LLM judgment on a 0–100 scale |
| **Max matches to deep-compare per article** (Max Finalists) | 3 | Rarely — raise for deeper comparison, lower under governor pressure |
| **Supported Languages** | Read-only | Reflects the languages scoring/dedup runs against |
| **Prompt Templates** | — | Links out to each GenAI Prompt Template in Prompt Builder. Read [Editing prompt templates safely](#editing-prompt-templates-safely) **before** changing anything — the scoring templates return a strict JSON shape and breaking it silently degrades the affected dimension to a baseline score |

> **Not on this screen.**
> - **Article length and title controls** — no scorer reads word counts. The one live knob (`Min_Title_Length__c`, default 10) is set directly on the `KB_Scan_Config__c` custom setting — see *Threshold settings not in the wizard* below.
> - **Auto-merge thresholds** — merges are always explicitly user-approved in the **Actions** tab (there's no unattended auto-merge), so a confidence-band gate would only silently block an approved merge. The remaining internal budgets (callout caps, the duplicate-flagging confidence cutoff) are governor-safety knobs — see *Pipeline knobs not in the wizard* below.

> **<a id="editing-prompt-templates-safely"></a>Editing prompt templates safely.** You can edit any GenAI Prompt Template in Prompt Builder, but the three scoring templates (`Evaluate_Completeness`, `Evaluate_Structure`, `Evaluate_Clarity`) are parsed by Apex against a **strict JSON return shape** (a `score` plus `issues` / `strengths` arrays). If an edit changes that return shape — or instructs the model to stop returning JSON — the scorer can no longer parse the response and the dimension **silently falls back to a baseline score of 60**, with no error surfaced in the UI. The fallback baseline is *not* a quality assertion, so the symptom is "every article scores ~60 on that dimension." **Safe to edit:** the instructional/criteria wording, the rubric, examples, tone, and which signals to weight. **Unsafe to edit:** the required output format / JSON schema, the field names the template is asked to emit, or anything that removes the JSON envelope. After editing a scoring template, run one assessment and confirm the dimension still shows varied (non-uniform-60) scores. Pipeline and AI Fix templates are more tolerant but follow the same rule — keep the documented return contract intact.

### Step 3 — Validate & Save

- Runs final validation confirming all configuration is consistent
- Shows a manual task checklist, including: assign permsets to Knowledge Managers, assign the non-shipped platform permissions (Data Cloud user / Prompt Template user) to running users, **activate the Knowledge article record page** (required — see [Installation Step 5](#activate-record-page)), and confirm your Data 360 index points at Knowledge articles
- Click "Complete Setup" → "Go to Assessments"
- Returning admins land on this step with a success banner and can navigate to any previous step to adjust configuration

> **Where settings are stored:** Configuration state is persisted in hierarchy custom settings (`KB_Scan_Config__c`, `KB_Score_Weight__c`, `KB_Pipeline_Config__c`, `KB_Vector_Search_Config__c`, `KB_Setup_Wizard_State__c`). No deployment is needed to change settings — re-run the wizard at any time.
>
> **Prompt tuning** is done via Salesforce Prompt Builder on the 12 deployed GenAI Prompt Templates — the setup wizard links out to each one.

### Threshold settings not in the wizard

A few low-level scoring thresholds are intentionally **not** surfaced in the Setup Wizard — they are advanced knobs most orgs never change. Set them directly on the `KB_Scan_Config__c` hierarchy custom setting (Setup → Custom Settings → **KB Scan Config** → Manage, or via the API/CLI):

| Field | What it controls | Default |
|-------|------------------|---------|
| `Min_Title_Length__c` | Completeness gate — titles shorter than this (characters) are flagged as a blocking issue (score 20) and skip the LLM. | 10 |

To change it via CLI, e.g.:

```bash
sf data update record --sobject KB_Scan_Config__c --where "SetupOwnerId='<orgId>'" --values "Min_Title_Length__c=12" --target-org <target-org>
```

Leaving these at their defaults is fine — the wizard no longer exposes them to keep the scoring-config screen focused on the settings teams actually tune.

### Pipeline knobs not in the wizard

These dedup-pipeline knobs are **live** (the pipeline reads them at runtime) but are pacing / internal-cutoff settings, not things a Knowledge Manager tunes day-to-day. They are not on the Setup Wizard; set them directly on the `KB_Pipeline_Config__c` hierarchy custom setting (Setup → Custom Settings → **KB Pipeline Config** → Manage, or via API/CLI). Custom-metadata defaults (`KM_Pipeline_Config__mdt.Default`) apply when no custom-setting row exists.

| Field | What it controls | Default | When to change it |
|-------|------------------|---------|-------------------|
| `Manual_Review_Threshold__c` | **Duplicate-flagging confidence cutoff.** In Tier 4, a detected duplicate/conflict pair is only written as a `Duplicate_Candidate__c` (surfaced in the **Actions** tab) when the model's confidence is ≥ this value. Pairs below it are recorded as "Clear" and not surfaced. | 50 | Raise it to cut noise in the **Actions** tab (fewer, higher-confidence candidates); lower it to surface more borderline pairs for human review. |
| `Max_SubAgent_Callouts__c` | **Tier 4 per-transaction pacing budget.** Caps the fact-extraction + comparison LLM calls Tier 4 makes in one transaction. This is a *pace*, not a coverage limit — when a run has more work than one transaction's budget, Tier 4 self-chains a continuation, so **every pair is still compared**. Lower values just spread the work (and its cost/latency) across more transactions. Despite the name, this isn't pacing against the Apex callout governor — the Einstein LLM call it caps doesn't count toward `Limits.getCallouts()`. | 20 | Rarely. Lower only if you want to spread cost/latency across more transactions; the chaining handles large runs automatically either way. Set too low to compare even one pair and the run stops with an actionable error rather than looping. |
| `Max_Callout_Limit__c` | **Tier 2 triage per-execution pacing budget.** Caps the relevance-triage LLM calls Tier 2 makes per execution. | 90 | Rarely — same pacing rationale as above; it isn't a hard governor ceiling. |

To change one via CLI, e.g. raise the flagging cutoff to 65:

```bash
sf data update record --sobject KB_Pipeline_Config__c --where "SetupOwnerId='<orgId>'" --values "Manual_Review_Threshold__c=65" --target-org <target-org>
```

> **No silent skips.** If `Max_SubAgent_Callouts__c` is set so low that Tier 4 cannot compare even a single article pair, the run does **not** quietly finish with partial coverage — it stops and stamps `KB_Assessment_Run__c.Status_Message__c` with a message telling you to raise the budget. For all workable values, the self-chaining continuation guarantees full coverage.

## Running Your First Assessment

1. Navigate to the **Assessments** tab and click **New Assessment**
2. **Assessment Details** — name the run (required) and add an optional description
3. **Select Articles** — filter and select Knowledge articles (or click "Select all matching filter" for bulk). A single assessment run covers up to **10,000 articles**; if a filter matches more, narrow it (or run multiple assessments) to cover your whole Knowledge Base.
4. **Preview** — review the inline Cost Preview panel (article scope, org-limit projections, and a credits notice)
5. Click **Start Assessment** — the modal closes back to the list
6. Watch real-time progress on the All Assessments tab (elapsed time, articles processed, pipeline phase)
7. Once complete, click the run to open its dashboard — Results, Dimensions, Recommendations

> **Index your Knowledge Base before running duplicate/conflict detection.** <a id="index-freshness"></a>The Duplication and Conflict dimensions find matches by searching the Data 360 semantic index — see [Search index: ADL vs custom](#search-index-adl-vs-custom). The article being assessed is read live, but the *candidates it's compared against* come from the index, so an article that isn't in the index yet is invisible to the search:
> - **A newly created (or freshly edited) article may not surface its duplicates** until the index has ingested it. Data 360 indexing is **not instant** — there's a refresh lag between publishing content and it appearing in the index.
> - This is most visible when you **create an article and immediately run an assessment** (e.g. during testing) — the article exists in Salesforce but not yet in the index, so genuine duplicate/conflict pairs are missed.
>
> **Recommendation:** ensure your Knowledge Base is fully indexed — i.e. wait for the Data 360 index/data stream to refresh after any bulk import or new authoring — *before* relying on the duplicate and conflict results. There is no in-app gate for this today; it's an operational step. (Completeness, Structure, Clarity, and Freshness are unaffected — they score the live article and don't use the index.)
