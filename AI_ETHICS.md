# AI Ethics

The Agentforce KB Readiness Evaluator uses large language models (via the
Salesforce Einstein platform and GenAI Prompt Templates) to score Knowledge
articles, detect duplicates and conflicts, and draft suggested rewrites. This
document describes how the tool uses AI and the principles we ask adopters to
uphold.

## How this project was built

Built by Salesforce forward deployed engineers with AI assistance — code
generated by Claude (Anthropic) under human direction, design, and review. The
prompts, architecture, and engineering decisions were made by the team, who
reviewed the output.

## How this tool uses AI

- **Scoring.** Three of the six scoring dimensions (Completeness, Structure,
  Clarity) are evaluated by an LLM against a fixed rubric. The other three
  (Freshness, Duplication, Conflict) are deterministic and do not call an LLM.
- **Deduplication.** LLM calls triage and compare candidate duplicate/conflicting
  article pairs.
- **AI Fix / Golden Record drafts.** On explicit user request, the tool generates
  a rewritten article body, or a merged "Golden Record", as a **Draft**.

## Principles

- **Human in the loop.** The tool never publishes Knowledge on its own. AI-scored
  results are advisory; AI-generated rewrites and merges are always created as
  Drafts for a human to review, edit, and publish. There is no unattended
  auto-merge and no auto-publish.
- **Transparency.** Scores carry the reasoning behind them, and a fallback
  baseline score is clearly labelled as a fallback ("Einstein evaluation
  unavailable … not a quality assertion") rather than presented as a real
  assessment.
- **The customer owns their data and their model.** All AI calls run inside the
  customer's own Salesforce org through the Einstein platform, subject to that
  platform's trust, data-handling, and residency guarantees. This project sends
  no article content to any third-party or external endpoint.
- **Access is enforced, not bypassed.** Draft writes run in the running user's
  context (`with sharing` + user-mode DML) and respect the org's object, field,
  and record-level access. The tool does not elevate a user past the access model
  the admin has configured.
- **AI can be wrong.** LLM output can be inaccurate, incomplete, or biased.
  Reviewers should treat scores and generated drafts as a starting point and
  apply their own judgement before acting on them, especially for
  customer-facing content.

## Reporting concerns

If you believe the tool is producing harmful, biased, or unsafe output, please
open a GitHub issue describing the behaviour (without including confidential or
personal data). For security vulnerabilities, follow [`SECURITY.md`](./SECURITY.md)
instead of filing a public issue.
